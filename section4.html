Identify the differences and advantages of model serving approaches

1. You need to generate daily revenue forecasts for thousands of retail stores every night at 2 AM. Which serving approach provides the most operational efficiency?

  • Configure a streaming pipeline using Delta Live Tables to process data continuously.
  • Initialize a standard cluster using Databricks Interactive to process data manually.
Correct Answer: A Batch inference using Databricks Workflows is the most cost-effective and efficient method for scoring large datasets offline on a scheduled cadence (e.g., nightly). Real-time and streaming endpoints are unnecessary when low-latency responses are not required.
2. A retail web application requires user-specific product recommendations within 50 milliseconds of a page load. Which serving approach meets this strict latency requirement?

  • Trigger an external web service to evaluate data chunks with asynchronous calls.
Correct Answer: A Databricks Model Serving provides highly available, low-latency REST API endpoints optimized for synchronous, real-time requests initiated directly by user interactions on web applications.
3. What is the primary operational advantage of streaming inference over traditional batch inference for financial fraud detection systems?

  • Streaming inference processes data manually as it exports from the system architecture.
Correct Answer: A Streaming inference evaluates unbounded streams of incoming data continuously, enabling rapid anomaly or fraud detection without waiting for scheduled batch processing intervals.

  • Batch inference optimizes streaming state management by scaling dynamically during continuous processing.
  • Batch inference eliminates cluster spin-up delays by scaling dynamically during synchronous processing.
Correct Answer: A Batch inference spins up ephemeral compute clusters specifically for the job duration, allowing it to efficiently process large historical datasets in parallel and scale resources appropriately before terminating.
5. When evaluating a hybrid architectural deployment, which constraint applies exclusively to streaming inference pipelines?

  • Streaming inference requires exposing endpoints directly across accessible web interfaces.

  • Streaming inference requires partitioning data physically across isolated storage containers.
Correct Answer: A Unlike batch or real-time inference which treat queries independently, streaming inference (via Structured Streaming or DLT) inherently involves checkpointing and state management to guarantee fault tolerance and exactly-once processing guarantees.

  • The application requires automatic state management for unbounded continuous streams.

7. How does data availability generally dictate the choice between batch inference and streaming inference methodologies?
